# 📋 System Requirements (Requirements v2)

**Document Purpose:** This document defines the quantifiable requirements (QR) and technical characteristics (TC) for the LaundroTwin platform, separated into MVP and Phase 2.

| ID      | Priority  | Category                | Requirement                                          | Scope / Rules / Dependencies                                                                                                                                                                                         | Acceptance Criteria                                                                                                | Constraints / Notes                                                               |
| :------ | :-------- | :---------------------- | :--------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------- |
| **R01** | **MVP**   | Infrastructure          | MQTT ingestion pipeline and validated telemetry data | Subscribe to MQTT, validate schema, attach `branch_id` and `machine_id`, and log raw/normalized events idempotently.<br><br>**Dependencies:** MQTT payload, `register_map_version`, Cloud / Time-series DB           | Valid events appear in the database within 2 seconds at p95; invalid payloads are rejected and reasons are logged. | Do not claim production scale support beyond the test targets.                    |
| **R02** | **MVP**   | IoT & Digital Twin      | Near real-time machine status dashboard              | Display status, remaining time, and temperature after defining the meaning of each field in the register map.<br><br>**Dependencies:** Register 4, 6, 7, 13; `machine_id`; `event_timestamp`                         | Dashboard displays the accurate latest event for each machine and updates within 2 seconds at p95.                 | Do not use the term "100% real-time".                                             |
| **R03** | **MVP**   | Business Intelligence   | Core business dashboard                              | Display revenue, cycle count, and utilization rate, filtered by branch and time period.<br><br>**Dependencies:** Paid counter / transaction event, program, `branch_id`                                              | Selected aggregated totals must be traceable to the source events of that specific branch and time period.         | Profit calculation is Phase 2.                                                    |
| **R04** | **MVP**   | Security & Multi-branch | Tenant isolation and RBAC                            | Owners see only authorized branches; Managers and Technicians are restricted by branch and role.<br><br>**Dependencies:** User, role, branch assignment, JWT/session                                                 | Authorization tests must explicitly deny cross-branch API access.                                                  | Define least privilege permissions before developing the UI.                      |
| **R05** | **MVP**   | Notification            | Business event alerts                                | Unique (idempotent) alerts for machine downtime, coin box thresholds, and low gas warnings.<br><br>**Dependencies:** Normalized events, alert rules, recipients                                                      | Events meeting the conditions generate a notification maximum once per cooldown window.                            | Use LINE Messaging API; do NOT use LINE Notify.                                   |
| **R06** | **MVP**   | Gas Management          | Early low gas warning                                | Evaluate low gas trends.<br><br>**Dependencies:** `gas_pressure`, `temperature`, dryer `state`, `timestamp`                                                                                                          | When the configured threshold is reached, the system sends an alert including the branch, sensor, and time.        | Do NOT use pressure alone to conclude there is a gas leak.                        |
| **R07** | **MVP**   | Business Logic          | Coin box estimation and reset                        | Estimate coin volume from calibrated cash/coin events; resets are allowed ONLY via explicitly mapped `coinbox_open` events.<br><br>**Dependencies:** Paid / coin event, `coinbox_open` event, capacity configuration | System displays the estimated value and logs every reset with timestamp and source.                                | Do NOT assume Register 12 acts as both door status and coin-box status.           |
| **R08** | **MVP**   | AI Assistance           | Executive Summary with safe function calling         | LLM can only call allowed analytics services; backend verifies roles and branch scopes; LLM must not execute arbitrary SQL.<br><br>**Dependencies:** Aggregated analytics APIs, RBAC context, audit log              | Owner can request MoM comparisons, but a Manager cannot retrieve data from other branches.                         | Weather context is Phase 2.                                                       |
| **R09** | _Phase 2_ | AI Assistance           | Promotion recommendations                            | Recommend off-peak periods based on historical usage rates. Results are suggestions only.<br><br>**Dependencies:** Time-series usage, program, optional campaign data                                                | The report specifies the branch, time period, metric, and rule used to identify low usage.                         | Price adjustments write-backs must be hardware-supported and approved separately. |
| **R10** | _Phase 2_ | Maintenance             | Predictive maintenance                               | Start with rule-based anomaly detection; ML can be used when sufficient failure labels and repair history are available.<br><br>**Dependencies:** `state`, `temperature`, error code, runtime, repair history        | Alerts must log the rule/model version and the data that triggered it.                                             | Do NOT claim time-to-failure prediction without labeled data.                     |
| **R11** | _Phase 2_ | Customer Experience     | Public machine status API                            | Publish only available/busy status and remaining time. Do not expose revenue, accounts, or internal branch data.<br><br>**Dependencies:** Sanitized Digital Twin API                                                 | Public endpoints are rate-limited and export only approved fields.                                                 | Recommend LIFF/web view; do NOT expose raw MQTT or database APIs.                 |
| **R12** | _Phase 2_ | External Data           | Demand analysis with weather context                 | Correlate weather data with historical usage ONLY after normalizing branch locations and times.<br><br>**Dependencies:** Weather API, branch location, time-series usage                                             | Analysis results specify the source data range, correlation method, and confidence limits.                         | Not required for MVP.                                                             |
